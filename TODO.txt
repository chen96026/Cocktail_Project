# 主線：把資料搬到 YAML，讓專案不用連 MySQL 也能跑
################################################################################

## 目標

現在啟動後端一定要有 MySQL，資料綁在特定一台筆電上，換電腦就跑不起來。
改成「YAML 當資料的唯一真實來源 + H2 記憶體資料庫」之後：

    git clone → mvn spring-boot:run → 資料自動長回來

不用裝 MySQL、不用匯資料、不用改 config。


## 採用方案

H2 in-memory + YAML 種子資料（不是拿掉 JPA 自己寫記憶體儲存）。

理由：Entity / Repository / Service / Controller 全部不用動，JPQL 也照跑，
新增編輯刪除都正常運作。要換回 MySQL 只是切一個 Spring profile。

## 實作順序（重要：先匯出再切換）

在家那台有資料的電腦上，照這個順序做，就完全不需要手寫任何 SQL：

[ ] Step 1. 先寫 exportSeed 端點，這時候還是連原本的 MySQL
            → 讀出所有 recipe / material / basewine / combination
            → 組成 YAML 寫到 src/main/resources/seed-data.yaml

[ ] Step 2. 啟動後端（連 MySQL），打一次匯出：
                curl -X POST http://localhost:8080/lastwine/exportSeed
            → 現有資料就變成 seed-data.yaml 了，不用手動抄

[ ] Step 3. 檢查 seed-data.yaml 內容正確（筆數、材料、四維度組合都有）

[ ] Step 4. 加 h2 dependency，把 datasource 切成 H2 記憶體模式
                spring.datasource.url=jdbc:h2:mem:cocktail
                spring.jpa.hibernate.ddl-auto=create-drop
            原本的 MySQL 設定移到 application-mysql.properties，用 profile 切

[ ] Step 5. 寫 DataSeeder：啟動時讀 seed-data.yaml 塞進 H2
            （@ConfigurationProperties 綁定 + CommandLineRunner）

[ ] Step 6. 關掉 MySQL，確認 mvn spring-boot:run 還是跑得起來、資料都在

[ ] Step 7. application.properties 裡的 MySQL 帳密可以整組拿掉了
            （Cloudinary 金鑰除外，除非做了 local 圖片方案）


## seed-data.yaml 格式

cocktail:
  seed:
    recipes:
      - enTitle: Screwdriver
        zhTitle: 螺絲起子
        image: https://res.cloudinary.com/<CLOUD_NAME>/image/upload/xxx.jpg
        method: |
          將冰塊放入杯中
          倒入伏特加後補滿柳橙汁
        baseWines: [Vodka]
        materials:
          - name: 伏特加
            quantity: 45ml
          - name: 柳橙汁
            quantity: 120ml
        combination: {mood: 愉悅, taste: 酸, tone: 暖, drunk: 微酣}

說明：
- 四維度組合直接內嵌在每杯酒下面，不用另外維護 combination_option
- 沒有分配組合的酒譜，combination 那行省略即可
- image 存 Cloudinary URL，換電腦照樣看得到圖


## 日常工作流程（做完之後）

  啟動：     mvn spring-boot:run

  新增一杯酒：
    1. 網頁 /AddRecipeForm 填完送出 → 存進 H2 記憶體，畫面立刻看得到
    2. 確定要留著 → curl -X POST http://localhost:8080/lastwine/exportSeed
    3. git diff 看 seed-data.yaml 的變化
    4. commit

  刪除 / 編輯 / 後台分配組合：一模一樣，改完 → 匯出 → commit

  ※ 匯出是「整份快照」不是增量，所以不管做了什麼操作都是同一套動作
  ※ 忘記匯出 → 重啟後回到 YAML 的狀態，等於白做工（這是本方案唯一的心智負擔）


## 注意事項

- exportSeed 寫的是 src/main/resources/，只有 mvn spring-boot:run
  （工作目錄在專案根目錄）時有意義 → 這支端點只在 local profile 註冊，
  打包成 jar 部署時不存在
- H2 記憶體模式每次啟動重建，UI 上新增的資料不會自動寫回 YAML
- 如果之後想要「不匯出也能保留」，可改 H2 檔案模式（jdbc:h2:file:./data/cocktail），
  但那個 .mv.db 二進位檔要 commit 才能跨電腦，版本控管難看且無法 merge，不建議


## 備案：如果不想先寫 exportSeed，要手動撈資料

資料表（由 JPA entity 推出，欄位名是 Hibernate 預設命名策略轉換後的結果）：

  recipe            recipe_id, en_title, zh_title, method, image
  material          material_id, material_name, material_quantity, recipe_id
  basewine          base_wine_id, name
  basewinelist      recipe_id, base_wine_id          (Recipe 與 BaseWine 的關聯表)
  combinations      combination_id, mood, taste, tone, drunk
  combination_option option_id, fk_recipe_id, fk_combination_id

撈資料的 SQL：

  SELECT r.recipe_id, r.en_title, r.zh_title, r.image, r.method,
         c.mood, c.taste, c.tone, c.drunk
  FROM recipe r
  LEFT JOIN combination_option co ON co.fk_recipe_id = r.recipe_id
  LEFT JOIN combinations c ON c.combination_id = co.fk_combination_id;

  SELECT recipe_id, material_name, material_quantity FROM material ORDER BY recipe_id;

  SELECT bl.recipe_id, bw.name
  FROM basewinelist bl JOIN basewine bw ON bw.base_wine_id = bl.base_wine_id
  ORDER BY bl.recipe_id;

（method 欄位是 TEXT 會換行，貼出來的時候注意格式）

       不處理的話 mvn spring-boot:run 會直接失敗

[ ] 5. 沒有任何測試
       唯一的 contextLoads() 需要連 MySQL，實際跑不起來
       （做完主線改用 H2 之後，這個測試就能跑了）
       投報率最高的起點：@WebMvcTest + MockMvc 測 controller 層
       重點涵蓋：新增酒譜的 multipart JSON part 綁定、404 行為、篩選器參數

[ ] 6. Entity 的 getter/setter 樣板約 200 行
       Recipe / Combinations / Material / BaseWine 四支，扣掉欄位宣告幾乎都是樣板
       Entity 不能用 record（JPA 要無參建構子 + 可變），只能靠 Lombok @Getter @Setter
       → 需要新增 dependency，先確認

[ ] 7. Admin 後台的組合過濾條件
       原本 !recipes.some(r => r.currentCombination?.combinationId === ...) 因為
       後端 DTO 是平的 combinationId，這個 filter 從來沒生效過，拆元件時已移除，
       維持「所有組合都顯示」的現狀行為。
       如果原意是「已被指派的組合不要再出現」，要改成 r.combinationId 比對，
       但要注意副作用：組合全配完後下拉會變空，就不能再改配對了
       （比較合理的版本：排除被別的調酒占用的組合，但保留自己目前那一個）
