## 現在的運作方式

    git clone → mvn spring-boot:run → 資料自動長回來

- 預設 profile：H2 記憶體資料庫，啟動時 DataSeeder 讀 src/main/resources/seed-data.yaml 載入
- mysql profile：mvn spring-boot:run -Dspring-boot.run.profiles=mysql
  連本機 MySQL（設定在 application-mysql.properties），不載入 YAML
- 圖片維持 Cloudinary，新增酒譜上傳圖片時需要網路 + 金鑰


## 決定紀錄

1. H2 dependency：加（runtime scope，版本跟 Spring Boot BOM）
2. 匯出功能：先不做，要改資料就直接改 YAML
3. Cloudinary：維持雲端，不做 local 版


## 初始資料來源

由 2026-09-28 的 MySQL dump 直接轉成 seed-data.yaml
- 48 杯酒 / 200 筆材料 / 93 筆基酒關聯 / 48 組四維度組合
- 用 SnakeYAML 讀回逐欄比對 SQL 原始資料，零差異
- 舊資料表 member（會員功能已移除）與未被使用的「待分配」組合沒有轉入


## seed-data.yaml 格式

cocktail:
  seed:
    recipes:
      - enTitle: Screwdriver
        zhTitle: 螺絲起子
        image: https://res.cloudinary.com/<CLOUD_NAME>/image/upload/xxx.jpg
        method: |-
          第一段介紹
          第二段介紹
        baseWines: [Vodka]
        materials:
          - name: 伏特加
            quantity: 45ml
          - name: 柳橙汁
            quantity: 120ml
        combination: {mood: 普通, taste: 酸, tone: 暖, drunk: 微酣}

說明：
- 四維度組合直接內嵌在每杯酒下面，不用另外維護 combination_option
- 沒有分配組合的酒譜，combination 那行省略即可
- image 存 Cloudinary URL，換電腦照樣看得到圖
- 基酒名稱要跟前端 constants/options.js 的 BASE_WINES value 一致


## 日常工作流程

  啟動：     mvn spring-boot:run

  新增 / 編輯 / 刪除酒譜、分配組合：
    1. 直接改 seed-data.yaml
    2. 重啟後端，畫面確認
    3. commit

  ※ 網頁 UI 上的新增、編輯、刪除都能正常操作，但只存在 H2 記憶體，
    重啟後回到 YAML 的狀態
  ※ 新酒譜的圖片：先從網頁新增一次拿到 Cloudinary URL（或到 Cloudinary 後台上傳），
    再把 URL 填進 YAML 的 image


## 之後如果想做匯出

- exportSeed 端點：讀 H2 全部資料 → 組成上面的 YAML 格式寫回 src/main/resources/seed-data.yaml
- 只有 mvn spring-boot:run（工作目錄在專案根目錄）時有意義，打包成 jar 時不該註冊
- 不建議改 H2 檔案模式（jdbc:h2:file:...），.mv.db 是二進位檔，版本控管難看且無法 merge

[ ] 6. Entity 的 getter/setter 樣板約 200 行
       Recipe / Combinations / Material / BaseWine 四支，扣掉欄位宣告幾乎都是樣板
       Entity 不能用 record（JPA 要無參建構子 + 可變），只能靠 Lombok @Getter @Setter
       → 需要新增 dependency，先確認

[ ] 7. Admin 後台的組合過濾條件
       原本 !recipes.some(r => r.currentCombination?.combinationId === ...) 因為
       後端 DTO 是平的 combinationId，這個 filter 從來沒生效過，拆元件時已移除，
       維持「所有組合都顯示」的現狀行為。
       如果原意是「已被指派的組合不要再出現」，要改成 r.combinationId 比對，
       但要注意副作用：組合全配完後下拉會變空，就不能再改配對了
       （比較合理的版本：排除被別的調酒占用的組合，但保留自己目前那一個）
